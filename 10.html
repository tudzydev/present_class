Feeling วันที่รหัสผ่านของสมาชิกทั้งสโมสรอยู่บนอินเทอร์เน็ต

ระบบสมัครสมาชิกชมรมถูกแฮก และรหัสผ่านของสมาชิกหลายร้อยคนถูกเผยแพร่ในที่สาธารณะ ผลสอบสวนพบว่าโค้ดเก็บรหัสผ่านแบบ plain text ในฐานข้อมูล และฟังก์ชันลงทะเบียนเป็น “god function” ยาว 300 บรรทัดที่ผสมทั้ง validate, hash (ซึ่งจริง ๆ ไม่ได้ hash), save และส่งอีเมลไว้ในที่เดียว ตอนผู้ตรวจสอบถามว่า “บรรทัดไหนรับผิดชอบการ hash?” — ไม่มีใครชี้ได้ เพราะมันไม่มีอยู่จริง สมาชิกนับร้อยถอนตัวจากความเชื่อมั่นที่พังลง

1) คุณรู้สึกอย่างไรกับเรื่องนี้ และระหว่าง “คนที่แฮก” กับ “ระบบที่ทำให้การแฮกคุ้มค่า” คุณคิดว่าใครควรรับผิดชอบมากกว่ากัน เพราะเหตุใด

2) หากโค้ดทั้งหมดอยู่ในฟังก์ชันเดียว 300 บรรทัด ใครจะกล้าแก้ไขมันเมื่อต้องเปลี่ยนอัลกอริทึม hash หรือย้ายฐานข้อมูล

เรื่องเล่าจากพี่เลี้ยง: “plain text ที่ไม่เคยถูกตั้งใจให้หลุด”

พี่แทน — Senior Security Engineer เล่าว่าสมัยทำงานปีแรก เขาเก็บรหัสผ่านแบบ plain text “ชั่วคราว” เพื่อความสะดวกในการ debug สามเดือนต่อมา test server โดนเจาะ รหัสผู้ใช้ 50,000 คนถูกนำไปขายบน dark web บริษัทต้อง reset รหัสทั้งหมดและถูกปรับตามกฎหมายคุ้มครองข้อมูล วันนั้นเขาเขียนกติกาชีวิตวิศวกรของตัวเองว่า “plain text ต้องไม่ผ่าน code review ของฉันอีกต่อไป” และ refactor ระบบลงทะเบียนโดยแยก “flow” ออกจาก “รายละเอียด” — flow อยู่ใน Use Case Service ส่วน hashing และ storage อยู่หลัง interface ที่สลับได้และทดสอบได้

ถอดรหัสวิธีคิดของคนสำเร็จ (สายความปลอดภัย):

  • ไม่เก็บ plain text เด็ดขาด — hash ด้วยอัลกอริทึมแข็งแรงพร้อม salt เสมอ
  • แยก “ผู้ประสานงาน” (Use Case Controller) ออกจาก “ผู้ลงมือทำรายละเอียด” (hasher / repository) ด้วย DI
  • เขียนเทสกรณีพังก่อนสำเร็จ: อีเมลผิด, รหัสสั้น, id ซ้ำ
  • ปฏิบัติต่อข้อมูลความลับเป็น concern แยก (Credential Entity) ไม่ปนกับข้อมูลตัวตน

Finding Sandbox: god function แห่งหายนะ

ทัศนคติประจำใบงาน: Failure is learning — ระเบิดในสนามซ้อมดีกว่าระเบิดในระบบจริง

พิจารณาโค้ดต่อไปนี้ แล้วหา “ระเบิดเวลา” ทุกจุดที่คุณมองเห็น

import sqlite3

def register_student(data: dict) -> str:
    # validate + เชื่อม DB + บันทึก ...ทั้งหมดในฟังก์ชันเดียว!
    if '@' not in data['email']:
        return 'invalid email'

    conn = sqlite3.connect('club.db')
    conn.execute(
        "INSERT INTO students (id, email, password) VALUES (?, ?, ?)",
        (data['id'], data['email'], data['password']),  # เก็บรหัสผ่านแบบ PLAIN TEXT!
    )
    conn.commit()
    return 'ok'

1) จงระบุ “ระเบิดเวลา” ในโค้ดนี้ให้ครบที่สุด (ความปลอดภัย, การทดสอบ, การบำรุงรักษา) และแต่ละลูกจะระเบิดเมื่อใด

2) คุณจะผ่า god function นี้ออกเป็นชิ้นส่วนที่มีหน้าที่ชัดเจนอย่างไร และชิ้นใดควรอยู่หลัง ABC เพื่อให้สลับ/ทดสอบได้

3) ลองให้ AI เสนอวิธี refactor ฟังก์ชันนี้มา 3 วิธี แล้วถกกับเพื่อน: วิธีใดน่าเชื่อถือที่สุด และคำตอบของ AI เชื่อถือได้มากน้อยเพียงใด (ฟังเพื่อนให้จบก่อนสรุปนะ)

📦 กล่องความรู้เสริม (อ่านเฉพาะเมื่อจำเป็น):
  • Use Case Controller: ผู้ประสาน flow (validate → hash → save) ไม่ลงมือทำรายละเอียดเอง
  • Dependency Injection: รับ UserRepository / PasswordHasher จากภายนอก → เทสด้วย Fake ได้
  • Security by Design: ไม่เก็บ plain text; hash พร้อม salt; validate ก่อน save; ตรวจ id ซ้ำ
  • GRASP Creator: ผู้ที่มีข้อมูลครบ (id, email ที่ validate แล้ว, hash) คือผู้สร้าง User
  • Protected Variations: ห่ออัลกอริทึม hash และเทคโนโลยีจัดเก็บด้วย ABC ที่มั่นคง
  • หมายเหตุงานจริง: ต้องการ Argon2id จริงให้ใช้ argon2-cffi แทน scrypt

ส่วนที่ 2: วิเคราะห์โค้ด (10 คะแนน)

import hashlib
import secrets
import re
from abc import ABC, abstractmethod
from dataclasses import dataclass


@dataclass(frozen=True)
class User:
    id: int
    email: str
    password_hash: str


class UserRepository(ABC):
    @abstractmethod
    def save(self, user: User) -> None: ...

    @abstractmethod
    def find_by_id(self, user_id: int) -> User | None: ...

    @abstractmethod
    def all(self) -> list[User]: ...


class InMemoryUserRepository(UserRepository):
    def __init__(self):
        self._users: dict[int, User] = {}

    def save(self, user: User) -> None:
        self._users[user.id] = user

    def find_by_id(self, user_id: int) -> User | None:
        return self._users.get(user_id)

    def all(self) -> list[User]:
        return list(self._users.values())


@dataclass(frozen=True)
class Email:
    value: str

    def __post_init__(self) -> None:
        normalized = self.value.strip().lower()
        if not re.fullmatch(r"[^@\s]+@[^@\s]+\.[^@\s]+", normalized):
            raise ValueError("Invalid email address.")
        object.__setattr__(self, "value", normalized)

    @classmethod
    def from_string(cls, value: str) -> "Email":
        return cls(value)

    def __str__(self) -> str:
        return self.value


class PasswordHasher(ABC):
    @abstractmethod
    def hash(self, plain_text: str) -> str: ...


class ScryptPasswordHasher(PasswordHasher):
    def hash(self, plain_text: str) -> str:
        salt = secrets.token_hex(16)
        digest = hashlib.scrypt(
            plain_text.encode(), salt=bytes.fromhex(salt), n=2**14, r=8, p=1
        ).hex()
        return f"scrypt${salt}${digest}"

    def verify(self, plain_text: str, stored: str) -> bool:
        _, salt, digest = stored.split("$")
        calc = hashlib.scrypt(
            plain_text.encode(), salt=bytes.fromhex(salt), n=2**14, r=8, p=1
        ).hex()
        return secrets.compare_digest(calc, digest)


class RegisterUserService:
    def __init__(self, users: UserRepository, hasher: PasswordHasher):
        self._users = users
        self._hasher = hasher

    def register(self, user_id: int, email: str, password: str) -> User:
        user_email = Email.from_string(email)

        if len(password) < 12:
            raise ValueError("Password must be at least 12 characters.")

        if self._users.find_by_id(user_id) is not None:
            raise ValueError("Student ID already exists.")

        password_hash = self._hasher.hash(password)
        user = User(user_id, str(user_email), password_hash)
        self._users.save(user)
        return user


repo = InMemoryUserRepository()
service = RegisterUserService(repo, ScryptPasswordHasher())

student = service.register(680001, "student@example.ac.th", "StudentPass123!")
print("Registered:", student.email)
print("Hash verified:", ScryptPasswordHasher().verify("StudentPass123!", student.password_hash))

1) โค้ดส่วนใดแสดงให้เห็นว่าระบบไม่เก็บรหัสผ่านแบบ Plain Text จงอธิบาย 3 คะแนน

2) การเรียก register(680002, 'invalid-email', 'StudentPass123!') จะเกิดอะไรขึ้น และข้อมูลจะถูกบันทึกหรือไม่ 2 คะแนน

3) การเรียก register(680003, 'valid@example.ac.th', 'short') จะเกิดอะไรขึ้น เหตุใดจึงกำหนดความยาวขั้นต่ำ 12 ตัวอักษร 2 คะแนน

4) การที่ Service รับ UserRepository เป็น ABC ช่วยให้การเขียน Unit Test ง่ายขึ้นอย่างไร 3 คะแนน
