Feeling เหตุการณ์ที่โรงอาหาร

ช่วงพักเที่ยงที่โรงอาหาร นักศึกษาคนหนึ่งยอดคงเหลือ 80 บาท แต่ระบบกระเป๋าเงินอนุญาตให้จ่ายค่าข้าวผัด 120 บาทได้ ยอดคงเหลือจึงกลายเป็น -40 บาท สิ้นเดือนเมื่อกระทบยอด บัญชีไม่ตรงกัน และป้าเจ้าของร้านต้องควักเงินตัวเองชดส่วนต่าง ทั้งที่ไม่มีใครตั้งใจโกงเลยแม้แต่คนเดียว

1) คุณรู้สึกอย่างไรกับเรื่องนี้ และเห็นใจใครมากที่สุด เพราะเหตุใด

2) ความผิดพลาดนี้ควรถูกป้องกันที่ “ความระวังของคนเขียนโค้ด” หรือที่ “การออกแบบระบบ” มากกว่ากัน เพราะเหตุใด

เรื่องเล่าจากพี่เลี้ยง: “วันที่ระบบยอมให้ถอนเกินยอด”

พี่บีม — Senior Python Engineer สาย fintech เล่าว่าสมัยอยู่ทีมระบบชำระเงิน โค้ดรุ่นแรก “ลืม” ตรวจสอบยอดคงเหลือในช่วงโปรโมชันถอนเงิน ผลคือบริษัทต้องชดใช้ค่าเสียหายให้ลูกค้าหลักล้านบาทในวันเดียว เขาบอกว่าบทเรียนที่แพงที่สุดวันนั้นสอนว่า “ระบบที่เกี่ยวกับเงิน ต้องไม่เชื่อใจผู้เรียกใช้แม้แต่นิดเดียว — กฎต้องอยู่ในวัตถุ ไม่ใช่อยู่ในคู่มือ”

ถอดรหัสวิธีคิดของคนสำเร็จ (สายระบบการเงิน):

  • ทำให้ invariant ชัดเจนและบังคับใช้ที่ขอบเขตของวัตถุ เช่น “ยอดห้ามติดลบ” ต้องถูกตรวจในคลาสเสมอ
  • ใช้ Domain Exception ให้ความผิดพลาดทางธุรกิจ “อ่านชื่อแล้วเข้าใจทันที” แยกจากความผิดพลาดเชิงเทคนิค
  • เขียนเทสกรณีพังก่อนสำเร็จเสมอ: จำนวนติดลบ, ศูนย์, ถอนเกินยอด, โอนให้ตัวเอง

Finding Sandbox: กระเป๋าเงินรุ่นเปราะบาง

ทัศนคติประจำใบงาน: Failure is learning — กระเป๋านี้ยังเป็นของจำลอง พังได้เต็มที่เพื่อเรียนรู้

พิจารณาโค้ดต่อไปนี้ แล้วทำนาย/ทดลองรันว่าเกิดอะไรขึ้น

class BankAccount:
    def __init__(self, account_number: str):
        self.account_number = account_number
        self.balance = 0.0

    def withdraw(self, amount: float) -> None:
        self.balance -= amount   # ไม่ตรวจว่ายอดพอไหม!

a = BankAccount("STU-680001")
a.balance = -9999   # ใครก็แก้ได้!
a.withdraw(500)     # ถอนเกินยอดได้เฉยเลย
print(a.balance)

1) ผลลัพธ์สุดท้ายคืออะไร และช่องโหว่ใดบ้างที่คุณพบในโค้ดชุดนี้

2) หากต้องออกแบบใหม่ให้ “ถอนเกินยอดเป็นไปไม่ได้” คุณจะวางกฎไว้ที่ใดของระบบ เพราะเหตุใด

3) ลองให้ AI เสนอวิธีป้องกันยอดติดลบมา 3 วิธี แล้วถกกับเพื่อน: วิธีใดน่าเชื่อถือที่สุด และคำตอบของ AI เชื่อถือได้มากน้อยเพียงใด (ก่อนถก อย่าลืมฟังเพื่อนให้จบก่อนนะ)

📦 กล่องความรู้เสริม (อ่านเฉพาะเมื่อจำเป็น):
  • Invariant: ความจริงที่ต้องเป็นจริงเสมอ เช่น ยอดคงเหลือห้ามติดลบ, จำนวนฝาก/ถอนต้อง > 0
  • Domain Exception: Exception ที่สื่อความหมายทางธุรกิจ เช่น InsufficientFundsError แยกจากความผิดพลาดเชิงข้อมูล เช่น ValueError
  • Python: @property แบบไม่มี setter ทำให้ balance อ่านได้จากภายนอกแต่แก้ไขผ่านเมธอดเท่านั้น
  • Convention: ชื่อขึ้นต้น _ สื่อว่า “ใช้ภายในคลาส” ไม่ควรเรียกจากภายนอก
  • Tell Don't Ask: อย่าดึงข้อมูลออกมาตัดสินใจเองข้างนอก — “บอก” ให้วัตถุทำหน้าที่ของมันเอง

ส่วนที่ 1: อ่านแผนภาพแล้วตอบคำถาม (10 คะแนน)

1) สัญลักษณ์ (property) กำกับหลัง account_number และ balance หมายความว่าอย่างไร และเหตุใด balance จึงไม่มี setter 2 คะแนน

2) สัญลักษณ์ + และ - หน้าสมาชิกหมายถึงอะไร และการตั้งชื่อ _assert_positive ด้วย underscore เดี่ยวสื่อความหมายว่าอย่างไร 2 คะแนน

3) “Domain Exception” คืออะไร ในแผนภาพคือคลาสใด และแตกต่างจากการใช้ ValueError อย่างไร 2 คะแนน

4) ลูกศร “inherits” จาก InsufficientFundsError ชี้ไปยัง Exception หมายถึงอะไร และการสร้างคลาส Exception ของตัวเองมีประโยชน์อย่างไร 2 คะแนน

5) ลูกศร “target” ที่วนกลับไปยัง BankAccount เองหมายความว่าอย่างไร และเกี่ยวข้องกับเมธอดใด 1 คะแนน

6) จงระบุ Invariant ของคลาส BankAccount มา 2 ข้อ 1 คะแนน

ส่วนที่ 2: วิเคราะห์โค้ด (10 คะแนน)

class InsufficientFundsError(Exception):
    """Domain exception: ยอดเงินไม่พอ"""


class BankAccount:
    def __init__(self, account_number: str):
        self._account_number = account_number
        self._balance = 0.0

    @property
    def account_number(self) -> str:
        return self._account_number

    @property
    def balance(self) -> float:
        return self._balance

    def deposit(self, amount: float) -> None:
        self._assert_positive(amount)
        self._balance += amount

    def withdraw(self, amount: float) -> None:
        self._assert_positive(amount)
        if amount > self._balance:
            raise InsufficientFundsError("Insufficient balance.")
        self._balance -= amount

    def transfer_to(self, target: "BankAccount", amount: float) -> None:
        self.withdraw(amount)
        target.deposit(amount)

    def _assert_positive(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("Amount must be positive.")

1) โค้ดส่วนใดป้องกันการฝากหรือถอนจำนวนติดลบและศูนย์ 2 คะแนน

2) เมื่อเรียก deposit(300) แล้วเรียก withdraw(120) ค่า balance จะเป็นเท่าใด จงแสดงวิธีทำ 3 คะแนน

3) หากยอดคงเหลือ 180 แล้วเรียก withdraw(500) จะเกิดอะไรขึ้น เพราะโค้ดบรรทัดใด 3 คะแนน
