Feeling อีเมล 27 ฉบับที่ไปไม่ถึง

มหาวิทยาลัยประกาศผลทุนการศึกษาผ่านอีเมล แต่มีอีเมล 27 ฉบับตีกลับ และที่เจ็บกว่านั้นคือ นักศึกษาคนหนึ่ง “หลุดทุน” ทั้งที่เกรดถึง เพราะในระบบทุนเธอคือ Student@Example.ac.th (พิมพ์ใหญ่ มีช่องว่าง) แต่ในระบบลงทะเบียนเธอคือ student@example.ac.th — ระบบมองว่าเธอเป็นคนละคน และอีเมลแจ้งเตือนจึงส่งไปผิดบัญชี

1) คุณรู้สึกอย่างไรกับเรื่องนี้ และความผิดพลาดนี้เกิดจาก “คนพิมพ์ผิด” หรือจาก “ระบบที่ยอมให้ค่าแบบเดียวกันมีความหมายต่างกัน” มากกว่ากัน

2) หากแต่ละโมดูลตรวจสอบอีเมล “คนละแบบ” ใครควรเป็นเจ้าของกฎที่แท้จริงของคำว่า “อีเมลที่ถูกต้อง”

เรื่องเล่าจากพี่เลี้ยง: “กฎ 12 แห่งที่ไม่มีใครเหมือนกัน”

พี่ยิ่ง — Senior Engineer ทีม e-commerce เล่าว่าโค้ดตรวจสอบอีเมลถูก copy-paste ไป 12 แห่ง บางแห่งเช็กแค่เครื่องหมาย @ บางแห่งใช้ regex คนละแบบ บางแห่งไม่เช็กเลย วันที่ฝ่ายการตลาดขอ “normalize อีเมลเป็นตัวพิมพ์เล็กทั้งหมด” ทีมต้องไล่แก้ 12 แห่ง และพลาด 2 แห่ง — ผลคือลูกค้าบางส่วนล็อกอินไม่ได้ทั้งสัปดาห์ หลังวิกฤตนั้นเธอสร้างคลาส Email ที่ “validate + normalize ตอนสร้างครั้งเดียว” และห้ามแก้ไขค่าหลังสร้าง ตั้งแต่นั้น bug เกี่ยวกับอีเมลกลายเป็นศูนย์ “ถ้ากฎอยู่ที่ 12 แห่ง แสดงว่าไม่มีกฎอยู่ที่ใดเลย”

ถอดรหัสวิธีคิดของคนสำเร็จ:

  • รวมค่าและกฎของแนวคิดหนึ่งไว้ในวัตถุเดียว (Value Object) — กฎเดียว ใช้ทั้งระบบ
  • บังคับ validate ตอนสร้างด้วย static factory — วัตถุที่สร้างสำเร็จ = ถูกต้องเสมอ (fail fast)
  • ทำให้ immutable — ค่าที่ validate แล้วต้องไม่ถูกทำให้เสียภายหลัง

Finding Sandbox: สองฟังก์ชัน สองมาตรฐาน

ทัศนคติประจำใบงาน: Failure is learning — ผิดหรือถูกไม่สำคัญ นี่คือการทดลองเพื่อเติบโต

1) เหตุใดฟังก์ชันทั้งสองจึง “เห็น” อีเมลเดียวกันต่างกัน และความเสี่ยงของการมีกฎหลายแห่งคืออะไร

2) คุณจะออกแบบอย่างไรให้ “กฎของอีเมล” อยู่ในที่เดียว และทุกโมดูลได้ประโยชน์โดยอัตโนมัติ

3) ลองให้ AI เสนอวิธีรวมศูนย์การ validate อีเมลมา 3 วิธี แล้วถกกับเพื่อน: วิธีใดน่าเชื่อถือที่สุด และคำตอบของ AI เชื่อถือได้มากน้อยเพียงใด (ฟังเพื่อนให้จบก่อนสรุปนะ)

📦 กล่องความรู้เสริม (อ่านเฉพาะเมื่อจำเป็น):
  • Value Object: วัตถุที่ไม่มี identity เทียบด้วยค่า และรวมค่า + กฎตรวจสอบไว้ในที่เดียว
  • Immutability: สร้างแล้วแก้ไขไม่ได้ — ค่าที่ validate แล้วไม่ถูกทำให้เสียภายหลัง
  • Static Factory: บังคับ validate ก่อนสร้างวัตถุ (fail fast) เช่น Email.from_string()
  • Normalization: strip + lower-case เพื่อให้ “ค่าเดียวกัน” ถูกมองว่าเหมือนกันทั้งระบบ
  • Python frozen dataclass: @dataclass(frozen=True) + __post_init__ + object.__setattr__ เพื่อ normalize ค่าในวัตถุที่แก้ไขไม่ได้
  • DRY: กฎเขียนครั้งเดียว ใช้ได้ทุกแห่ง ไม่ต้อง copy-paste การตรวจสอบ

ส่วนที่ 1: อ่านแผนภาพแล้วตอบคำถาม (10 คะแนน)

1) «dataclass frozen» ที่กำกับคลาส Email หมายความว่าอย่างไร และเหตุใด Immutability จึงสำคัญต่อ Value Object 2 คะแนน

2) เมธอด from_string(value) มีบทบาทอะไร และรูปแบบนี้เรียกว่าอะไร 2 คะแนน

3) __post_init__() ใน frozen dataclass มีบทบาทใด และเหตุใดจึงต้องใช้ออปเจกต์ object.__setattr__ ในการแก้ค่า 2 คะแนน

4) ลูกศร “raises” ชี้ไปยัง ValueError หมายถึงพฤติกรรมใด และเกิดขึ้นเมื่อใด 2 คะแนน

5) เหตุใดเมธอด equals(other) จึงเปรียบเทียบด้วย “ค่า” แทน identity ของออบเจกต์ 1 คะแนน

6) เมธอด __str__() มีประโยชน์อย่างไรต่อการใช้งานจริง 1 คะแนน

ส่วนที่ 2: วิเคราะห์โค้ด (10 คะแนน)

import re
from dataclasses import dataclass


@dataclass(frozen=True)
class Email:
    value: str

    def __post_init__(self) -> None:
        normalized = self.value.strip().lower()
        if not re.fullmatch(r"[^@\s]+@[^@\s]+\.[^@\s]+", normalized):
            raise ValueError("Invalid email address.")
        object.__setattr__(self, "value", normalized)

    @classmethod
    def from_string(cls, value: str) -> "Email":
        return cls(value)

    def equals(self, other: "Email") -> bool:
        return self.value == other.value

    def __str__(self) -> str:
        return self.value


student_email = Email.from_string("Student@Example.ac.th ")
print(str(student_email))

another_email = Email.from_string("student@example.ac.th")
print(student_email.equals(another_email))

1) ผลลัพธ์ของ Email.from_string("Student@Example.ac.th ") คืออะไร จงอธิบายการทำงานทีละขั้นตอน 3 คะแนน

2) การเรียก Email.from_string("student@invalid") จะเกิดอะไรขึ้น เพราะเหตุใด 2 คะแนน

3) เหตุใด equals ระหว่าง "Student@Example.ac.th " กับ "student@example.ac.th" จึงคืนค่า True 3 คะแนน

4) หากพยายามแก้ไข student_email.value = "x@y.z" จะเกิดอะไรขึ้น เพราะเหตุใดจึงออกแบบเป็น frozen 2 คะแนน
